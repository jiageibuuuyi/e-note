# ADR-0003：开发阶段的继承、有效字段和附件状态契约

日期：2026-10-25

状态：开发文档采用的基线；实现与平台验证尚未开始。产品细化默认值在首次原型评审中核对，不标成用户已逐项确认。

## 背景

用户要求提供能自行据以开发的文档。ADR-0002保留跨平台分层单体方向，本记录补全直接影响各模块一致性的数据契约。

## 决定

1. 采用records中的独立字段与inherit_mask表达六组字段继承，不再另建record_overrides表。位为1表示继承，位为0表示独立；显式无deadline与继承区分。
2. effective_records作为事务内同步维护的可重建投影，供搜索、排序、日历与提醒统一读取。记录字段与投影由同一个写入事务维护。已完成记录从completion_snapshots获取历史值，重开恢复动态继承。
3. V1开发默认一层子任务；根任务不能继承，parent_id与kind创建后不变，完成父项与重开子项遵守明确顺序。
4. 附件导入首版统一使用复制、校验、登记、清源流程，包括同盘Move；同盘原子移动作为后续可测优化。这不改变拖入移动语义，但增加同盘操作的时间与空间成本。
5. 附件回收区采用逻辑标记，保留物理位置，避免移除/恢复时重复搬迁。永久清理使用可恢复作业。
6. 剪贴板/拖放移动的源清理责任必须唯一；只有目标登记且源身份可靠时可清理，不确定则报告未完成。

## 成本与验证

投影带来额外维护责任，必须用事务与集成测试保证各入口同步更新。不能把数据库直接改字段作为受支持业务操作。全部关键字段规则见[开发实施指南](../开发实施指南.md)，完整初始表结构见[参考SQL](../database/001_initial.sql)。

首版统一移动流程减少恢复分支，代价是同盘也需暂存空间；空间不足明确失败，不降级成用户未选择的复制。使用故障注入验证每个持久化阶段，并测试恢复其他设备备份时不执行旧删除作业。

配套SQL验证只证明结构和部分约束可执行，不证明文件系统、C#服务或桌面宿主已实现。
