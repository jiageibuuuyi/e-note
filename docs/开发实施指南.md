## 4. 核心类型与继承算法

以下代码为业务契约示例，不包含 UI，采用 `DesktopNotes.Domain` 命名空间。对应实现文件名见第 3 节；拆分文件不改变类型名。

```csharp
namespace DesktopNotes.Domain;

public enum RecordKind { Task = 0, Note = 1 }
public enum RecordStatus { Active = 0, Closed = 1 }
public enum Priority { Highest = 0, High = 1, Normal = 2, Low = 3 }
public enum DueKind { None = 0, Date = 1, Instant = 2 }

[Flags]
public enum InheritField
{
    None = 0, Publisher = 1, Assignee = 2, Priority = 4,
    Start = 8, Due = 16, AttachmentRoot = 32, All = 63
}

public sealed record DueSpec(DueKind Kind, DateOnly? Date,
    DateTimeOffset? Instant, string? ZoneId)
{
    public static DueSpec Empty => new(DueKind.None, null, null, null);
}

public sealed record EffectiveFields(string? Publisher, string? Assignee,
    Priority Priority, DateTimeOffset? Start, DueSpec Due, Guid? AttachmentRootId);

public static class InheritanceResolver
{
    public static EffectiveFields Resolve(EffectiveFields own,
        EffectiveFields? parent, InheritField mask)
    {
        if (parent is null)
        {
            if (mask != InheritField.None)
                throw new ArgumentException("root_cannot_inherit", nameof(mask));
            return own;
        }
        bool Follow(InheritField f) => (mask & f) != 0;
        return new(
            Follow(InheritField.Publisher) ? parent.Publisher : own.Publisher,
            Follow(InheritField.Assignee) ? parent.Assignee : own.Assignee,
            Follow(InheritField.Priority) ? parent.Priority : own.Priority,
            Follow(InheritField.Start) ? parent.Start : own.Start,
            Follow(InheritField.Due) ? parent.Due : own.Due,
            Follow(InheritField.AttachmentRoot) ? parent.AttachmentRootId : own.AttachmentRootId);
    }
}
```

存储 `inherit_mask` 的 bit=1 表示继续继承。新子任务默认 63；父任务为 0。编辑子字段时清除对应位并保存独立值，恢复继承时置回对应位。独立 deadline 为空使用 `DueSpec.Empty`，不拿 NULL 作为“自动继承”的判断。

示例：父任务责任人“甲”，子任务跟随 → 改父为“乙”时子变“乙”；子单独设为“乙”并清除继承位 → 父改为“丙”时子仍为“乙”。即使数值相同，也不能凭值相同推断恢复继承。

日期、时区、精度是一个整体覆盖字段；不要出现继承父任务日期但保留子任务旧时间的混合值。标题、正文不继承；新建子任务必须输入自己的描述。

### 4.1 名称生成与搜索函数

```csharp
using System.Globalization;
using System.Text;
using System.Text.RegularExpressions;

namespace DesktopNotes.Domain;

public static class DisplayName
{
    public static string Create(string? title, string? body)
    {
        if (!string.IsNullOrWhiteSpace(title)) return title.Trim();
        var text = Regex.Replace(body ?? "", @"\s+", " ").Trim();
        var e = StringInfo.GetTextElementEnumerator(text);
        var output = new StringBuilder();
        int count = 0;
        while (e.MoveNext())
        {
            if (count++ == 30) return output.Append('…').ToString();
            output.Append(e.GetTextElement());
        }
        return output.ToString();
    }
}

public static class LiteralSearch
{
    public static bool Matches(string? query, params string?[] fields)
    {
        var q = (query ?? "").Trim();
        return q.Length == 0 || fields.Any(x =>
            x?.Contains(q, StringComparison.Ordinal) == true);
    }
}
```

服务层使用 `string.IsNullOrWhiteSpace(title) && string.IsNullOrWhiteSpace(body)` 拒绝空记录。SQL 的 `trim` 只是基础防线，不覆盖全部 Unicode 空白；不要把数据库 CHECK 当成完整业务校验。输入 UTF-16 不完整代理项和 NUL 字符应拒绝，避免 .NET 与 SQLite 表示差异。

## 5. 数据库设计与事务

### 5.1 实体和存储约定

使用配套 [001_initial.sql](database/001_initial.sql) 作为起始迁移。数据库在本机应用数据目录，不能放在网络共享盘；附件目录独立。每条连接开启外键与 5 秒 busy timeout，首次初始化设置 WAL。源文件移动相关数据库写入采用 `synchronous=FULL`，但仍不承诺对所有硬件断电绝对安全。

| 表 | 写入者及用途 |
|---|---|
| records | RecordService，用户输入的独立字段、父 ID、继承掩码、状态和版本 |
| effective_records | ProjectionBuilder，仅由 RecordService 所在事务调用；搜索/排序/日历使用的有效字段 |
| completion_snapshots | RecordService，完成时冻结有效字段的 JSON（带 schemaVersion=1） |
| storage_roots | SettingsService，根目录映射；被使用时禁止直接删除 |
| attachments | AttachmentService，已登记正式附件及逻辑回收状态 |
| attachment_jobs/items | ImportWorker/RecoveryService，共用串行写入队列，持久化移动阶段及逐文件清单 |
| reminder_deliveries | ReminderScheduler，通知去重与发送尝试 |
| drafts | 编辑器经应用服务保存；允许内容暂时不满足记录保存约束 |
| settings | 设置服务，类型化读取 JSON，版本控制 |
| schema_migrations | MigrationRunner，已完成迁移版本 |

UUID 存小写标准字符串；绝对时间存 UTC Unix 毫秒，日期存 `yyyy-MM-dd`，枚举值采用本指南固定整数。时间边界存于投影中，系统时区变化时重建。文件夹清单路径统一 `/` 分隔，最终文件系统操作使用平台路径 API。

`effective_records` 是可重建的投影，不是第二个数据源：活动记录由自身字段和父记录求得，已关闭记录由完成快照求得；草稿不参与投影。软删除记录保留投影且不搜索，恢复时重新校验并求值。每次提交必须更新源记录和相应投影，不使用后台最终一致性，否则父任务改完可能短暂出现错误提醒。

此设计将计划书中独立的 `record_overrides` 细化为 `records.inherit_mask` + 独立字段，避免再建一套重复覆盖表。行为保持逐字段继承不变。

### 5.2 统一写入流程

1. 通过应用级单写队列进入后台数据库执行上下文，不占用 UI 线程。
2. `BEGIN IMMEDIATE`，按 ID 加载当前记录和版本。
3. 对比 `ExpectedVersion`；不一致返回 `Conflict`，不覆盖。
4. 修改输入字段/掩码；计算父任务及所有受影响的活动子任务新有效值。
5. 校验标题/内容、日期、父子关系，任一失败整笔回滚并返回冲突记录 ID。
6. 更新自身版本；继承导致有效值变化的子任务也递增版本并更新时间。
7. 更新有效投影，取消或替换相关提醒计划；数据库提交。
8. 提交成功后发出一个 `RecordsChanged` 通知，包含受影响 ID 和变更版本；UI 刷新，调度器重排。

事务中不复制附件、不显示弹窗、不调用通知 API，也不等待用户。任何依赖用户决定的操作先返回有结构的错误，再由新命令执行。

数据库驱动的 Async 方法并不意味着真正异步 I/O；Microsoft.Data.Sqlite 官方说明相关方法仍同步执行。因此 SQL 在受控后台执行，UI 只 await 应用服务，不能在 UI 线程调用 `ExecuteNonQueryAsync` 后便认为不会卡顿。[Microsoft.Data.Sqlite 异步限制](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/async)

### 5.3 搜索与默认排序 SQL

```sql
SELECT * FROM record_search
WHERE kind = $kind AND deleted_utc_ms IS NULL
  AND ($all_status = 1 OR status = $status)
  AND ($q = ''
       OR instr(title, $q) > 0 OR instr(body, $q) > 0
       OR instr(coalesce(publisher, ''), $q) > 0
       OR instr(coalesce(assignee, ''), $q) > 0)
ORDER BY priority ASC,
         (due_boundary_utc_ms IS NULL) ASC,
         due_boundary_utc_ms ASC,
         created_utc_ms ASC, id ASC
LIMIT $take OFFSET $skip;
```

优先级 0 最高，因此 SQL 用 ASC。`instr` 表示字面量包含，`%` 和 `_` 不作通配符。不把全部字段拼接起来搜索，否则“标题末尾+正文开头”可能产生不存在的连续词。

用户排序采用枚举白名单生成 ORDER BY：Priority、Deadline、Created 三种字段，分别 Asc/Desc，最多三项且不重复。缺省补 ID ASC 稳定排序；Deadline 无值始终放最后，即使降序也一样。不能直接拼接用户输入的 SQL 字段名。列表分页与总数查询使用同一过滤条件；读取一致快照，切换查询后重置分页。清空搜索不清空其他筛选。

| Code | 触发与处理 |
|---|---|
| Validation | 空内容、日期组非法、开始晚于边界；保留编辑内容 |
| Conflict | 旧版本写入；显示当前版本，让用户重新合并，不自动覆盖 |

| AlreadyExists | 创建 ID 已存在；按 ID 查询结果 |
| NotFound | 记录不存在；关闭过期详情并提示 |
| PathUnavailable | 指定目录离线或无权限；重试或改选，不自动换目录 |
| InsufficientSpace | 目标空间不足；不开始源项清理 |
| SourceChanged | 源身份或内容改变；保留源项，显示冲突 |
| UnsupportedCapability | 系统能力不可用；保持可操作模式，解释原因 |
| Busy | 写入锁超时或同一记录有未结束附件作业；可重试 |

### 6.1 状态操作顺序

- 完成子任务：冻结 EffectiveFields 快照，置 Closed/closed_at，停提醒；父任务不自动完成。
- 批量完成：先校验，子任务先闭合，再闭合父任务，全部一个事务；未完成子任务存在时 `includeChildren=false` 返回 ActiveChildren。
- 重新打开子任务：必要时先重开父任务；恢复继承计算与日期校验，通过后统一提交；删除旧完成快照，因为不提供逐次完成历史。
- 软删除父任务：同一 deletion_batch_id 标记父任务和本次尚未删除的子任务；先标子项。此前单独删除的子项保留原批次。
- 恢复父任务：按该删除批次恢复，不自动恢复旧批次；当前继承值不合法则回滚并让用户在恢复流程中修正。
- 永久删除：附件清理是独立有日志的作业，清理失败保留记录和状态供重试；附件处理完、关联作业终结后才能物理删除子记录及父记录。不得使用数据库级联删除来替代磁盘清理。

## 7. 日期、提醒和日历实现

### 7.1 日期语义

`DueKind.None` 所有日期字段空；Date 只存本地自然日期；Instant 存 UTC 时刻和用于编辑回显的时区 ID。显示默认使用当前系统时区。时区 ID 在平台服务中统一解析，导入无法解析时要求选择替代时区，不默认为 UTC。

- Date 的逾期边界为该日期次日的本地起始时刻转换成 UTC；不写成固定“23:59:59”。
- 夏令时导致某本地时刻不存在时，编辑界面要求调整；出现两种 UTC 解释时要求选择偏移量。日期边界遇到不存在的午夜，取当日首个有效时刻；重复午夜取较早实例。
- Instant 的边界就是 UTC 时刻。`now >= boundary` 且 Active 才逾期。
- 开始时间相对 Instant 不得大于截止时刻；相对 Date 必须小于次日边界。
- 系统时区改变时重新计算所有日期型投影边界及日历显示，绝对时间本身不移动。

### 7.2 调度

只维护一个提醒调度器，通过下一条边界设置可取消定时器，另设 60 秒兜底重算。启动、数据库提交、系统恢复、跨日、时区变化触发重排。纯面板颜色不落库，它是状态的计算结果。

通知开启时按照第 1.2 节默认策略，使用 `(record_id,due_fingerprint,stage,occurrence_key)` 去重。fingerprint 来自有效 DueSpec 的规范序列化，不用普通更新时间，否则改正文也会重发提醒。主子字段变化涉及 deadline 时取消旧计划，重排新计划。

数据库与系统通知之间没有跨系统事务，不能承诺 exactly-once。先写 `claimed` 再尝试投递；成功写 `delivered`；失败写 `failed`。进程重启后遇到不确定的 claimed，不自动逐条重发，以一条恢复摘要提示未完成事项，避免重复轰炸。关闭通知仍计算面板状态；隐藏窗口后面板颜色自然不可见，不能描述为后台颜色提醒可见。

### 7.3 月历

默认按 Due 查询：Date 按原日期分组，Instant 转换到当前时区的日期后分组。Start/Created/Closed 以 UTC 月范围查询，按本地日分组；左边界包含、右边界不包含。没有对应时间的记录进入“无日期”。已完成记录按冻结字段展示。子任务单独出现，结果带 parent_id 可查看来源。

## 8. 附件入口、作业状态机与恢复

这是 V1 中需要最多故障测试的模块。业务目标是移动，但不能用一次无日志的 `File.Move` 或 `Directory.Move` 代替完整流程。

### 8.1 接口与输入


一次 batch 中每个顶层文件/目录对应一个独立 job，job 固定 attachment_id，重试复用。Drag 不论修饰键均 Move；剪贴板只有可靠剪切标记时 Move，否则 Copy；FilePicker 默认 Copy，在按钮文字写明“复制添加”。传入路径去重并去除被同批父目录包含的子路径，避免同一个文件被移动两次。

应用支持本地文件管理器的真实磁盘条目。纯文本路径不导入，虚拟文件数据流与截图位图不在 V1。对已由本应用管理的路径拒绝再次移动，提示使用任务内附件管理；第一版不做跨任务转移快捷操作。

### 8.2 目录布局

```text
<系统应用数据目录>/DesktopNotes/
  data/app.db
  backups/database/
  logs/
<用户附件根目录>/
  .desktopnotes-staging/<job-id>/payload/
  tasks/<record-id>/<attachment-id>/<原文件名或目录名>
```

生成目录只使用 UUID。源目录内相对结构及空目录保留；目录外链接不递归跟随。路径校验必须解析实际路径/文件身份，检测源=目标、目标在源内、重解析点、管理目录自身；不得只做字符串 StartsWith。

同名文件分配不同 attachment_id，不能覆盖。附件移除采用**逻辑回收区**：设置 `trashed_utc_ms`，磁盘位置不变，UI 从普通列表移到回收区；恢复清除标记。这样不为每次移除增加跨盘搬迁。

### 8.3 默认采用统一的复制验证后清理流程

V1 首先让同盘和跨盘都通过同一条恢复流程，降低两套实现风险；同盘原子重命名作为有测试后的优化，不是首发前置条件。产品仍是 Move，因为成功时源项被移除；代价是同盘也可能需要额外空间和 I/O，界面显示容量不足，不能偷偷变成 Copy。

| 状态 | 持久化内容与允许动作 |
|---|---|
| planned | 规范源/目标、设备 ID、稳定 job/attachment ID、完整目录清单已落盘 |
| copying | 后台流式复制，进度只在内存频繁变化，数据库按阶段/节流记录 |
| verified | 所有文件及空目录已就位，目标哈希和源快照一致，验证清单落盘 |
| published | 暂存 payload 重命名到目标正式位置；目标仍由本 job 独占 |
| registered | attachments 记录和 job 状态同一数据库事务完成；此后不能因取消删掉目标 |
| cleaning | 仅 Move；逐项校验源身份后移除，记录每项结果 |
| done | Copy 已登记或 Move 源清理完成 |
| source_cleanup_pending | 目标已保存，但部分源项不能移除，显示明确状态 |
| failed | 尚未登记的失败，源项完整保留；可以重试 |
| cancelled | 登记前取消，不删源；清理受管理暂存文件 |
| needs_review | 崩溃后证据不足、源变动或不同设备恢复，等待用户处理 |

默认一个作业传输，避免多目录一起拖入时造成磁盘争用；最多一个清理操作处理同一源身份。复制使用固定大小缓冲，例如 1 MiB；摘要 SHA-256 分块计算，不能 `ReadAllBytes`。目录复制完成后读取目标再次校验哈希；导入中源文件变化返回 SourceChanged。耗时操作不放入 SQLite 事务。

“验证+删除”之间还有并发风险。平台文件操作端必须提供基于打开句柄/身份及必要锁的 `RemoveVerifiedSource` 能力；无法可靠约束文件被替换/改写时返回不确定，进入 source_cleanup_pending，不按路径盲删。仅比较大小与修改时间不充分。具体 Windows 句柄删除/共享标志以及 macOS/Linux 对应机制须在平台原型验证，未验证前禁止针对真实源执行清理。

文件夹源清理按清单逐文件、再自底向上删除空目录，绝不用递归强制删除目录。清单之后新增的文件保留；遇到变化停止相关清理并展示差异。整个目录验证前不开始清理其中任意源文件。

### 8.4 中断与幂等恢复

| 重启时证据 | 恢复动作 |
|---|---|
| 暂存不完整、源存在 | 保持可重试，可清理本 job 暂存；不删源 |
| 暂存完整且清单 verified | 复验目标清单后继续 publish/register |
| 目标存在但 job 尚为 verified | 校验确定由该 job 写入后补记 published；有冲突则 needs_review |
| 附件已登记，源仍存在 | 重新核验身份，只有同一设备且证据可靠才继续清理 |
| 源已消失，某 item 未标 removed | 目标已验证且源清理记录足够时补标；不猜测丢失原因 |
| 源目标都存在但哈希不同 | 保留两端，needs_review；禁止覆盖 |
| 目标缺失而源已清理 | 标记附件 missing，报告数据完整性故障，提供备份恢复入口 |
| 不同机器恢复的备份含旧 job | 转为 needs_review/终结审计，绝不执行原设备绝对路径删除 |

用户取消：registered 前可停止并清理自己的暂存，源不动；registered 后停止剩余源清理并保留正式附件，状态变 source_cleanup_pending，文案“附件已保存，移动未全部完成”。不能承诺取消后还原整个目录。

附件目录迁移使用同样作业：复制并验证新位置 → 事务更新引用 → 清理旧受管理位置。目标失败保持旧引用。任务目录设置变化和继承变化只影响未来新附件，不自动创建迁移作业。

### 8.5 系统拖放与剪贴板

Windows 原型要验证文件列表及 copy/cut 意图格式、拖放效果回传和完成通知，避免应用与源程序各删一次。未完成校验时不能向源端宣告最终成功。优先将输入数据对象转换为本地路径/可靠来源信息后释放 UI 对象，传输在后台完成；如果某系统传输协议要求源端清理，与本地导入服务必须明确唯一清理责任者。

剪切完成通知只对原 `ClipboardToken` 仍匹配时发送；若用户导入期间复制了新内容，保留新剪贴板。Linux 剪切语义按所选桌面文件管理器验证，不把能读 URI 列表当作已经支持 move。[Avalonia 剪贴板平台差异](https://docs.avaloniaui.net/docs/how-to/clipboard-how-to)

## 9. 窗口与平台适配

### 9.1 模式建模

将模式拆成两个独立状态：`PlacementMode = Topmost | EmbeddedDesktop` 与 `Visibility = Shown | TrayHidden`。隐藏不改变 PlacementMode，恢复回原模式；新增普通窗口模式只作失败时用户可选的替代，不冒充桌面模式成功。

### 9.2 Windows 原型顺序

1. 创建无边框但可调整大小的普通面板，先验证中文输入和文件拖放。
2. 验证置顶，模式变化不循环抢焦点，详情窗口能在面板上方编辑。
3. 单独实现桌面宿主发现、连接、解除连接、恢复四个操作，不把窗口类名/句柄保存在业务记录。
4. 针对宿主方案验证 Win+D/显示桌面、桌面图标命中、OLE 文件拖放、IME、DPI、Explorer 重启。
5. 从 EmbeddedDesktop 切回 Topmost 前解除宿主、恢复窗口样式及坐标；操作失败恢复上一稳定模式并提示。
6. 建立托盘后再允许主窗口完全隐藏；如果托盘初始化失败保留任务栏入口，不能让程序无恢复途径。

`SetWindowPos(HWND_BOTTOM)` 只说明 Z 序变化，不作为桌面嵌入实现。桌面宿主方案依赖实际系统行为；本文不提供未经本机验证的 WorkerW“万能代码”。原型报告必须包含宿主查找结果、Windows 构建、窗口切换录像/截图和输入/拖放结果，失败就停在平台层修复。[Microsoft SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)

### 9.3 生命周期与多屏

启动：单实例锁 → 读设置 → 数据库迁移/作业对账 → 建立托盘 → 创建面板 → 恢复位置/模式 → 启动提醒。重复启动激活现有实例，不再打开第二个数据库写入器。

关闭按钮隐藏到托盘，托盘退出先停收新作业、保存草稿、持久化作业进度，再释放窗口和连接；退出期间不无限等待大文件复制。取消系统关机会造成阻塞，应优先持久化恢复状态并允许退出。

位置使用 DIP 相对工作区保存，并保存监视器标识和缩放。监视器消失时回到主屏可见区域，保留至少完整标题栏；保存事件防抖 500ms。锁定位置只禁拖动，不禁点击。快捷键冲突时显示禁用状态和修改入口，不悄悄占用已有键。

### 9.4 macOS / Linux 路线

主界面与数据接口共用，分别实现菜单栏/托盘、通知、登录项、文件管理器、剪贴板及窗口层级。macOS 至少验证 Spaces、多屏和“显示桌面”；Linux 明确 GNOME/KDE、X11/Wayland 组合。平台能力不同需在发行说明中列明，用户接受替代行为后才能声称该平台交付。

Windows V1 前做最小三端运行验证；缺 Mac/Linux 环境时可以继续开发共享业务，但保持对应验证未通过状态，不能以跨编译代替运行。签名、公证和发行包属于后续平台发布任务，不是 .NET 共享工程自然完成的能力。

## 10. 界面实现约定

### 10.1 面板

标题栏：产品名、新建、菜单；主内容：任务/笔记切换、搜索框、排序入口、虚拟化列表；底部：日历、归档、设置。折叠行主体只显示名称，可配完成勾选框和状态边线；完整字段放在展开区与详情。空列表、搜索零结果、保存失败各有明确状态。

使用 `ListBox`/等效虚拟化集合，禁止把所有记录转成永久存活的控件。每次只展开一个 ID，展开高度上限为面板内容高度的一半，超出用内部滚动并提供详情入口。选中、展开和键盘焦点分别建模，不将选中等同完成。

单击/双击在 `TaskRowInteraction` 统一处理：第一个 ClickCount=1 执行展开；ClickCount=2 只打开详情，不执行第二次折叠。对已展开行的收起延迟到系统双击窗口结束后，双击则取消收起。滚动、附件按钮、完成框消费事件，不触发整行操作；拖放启动后取消候选点击。

### 10.2 详情和编辑

详情字段：标题、正文、优先级、日期、人员、附件目录、附件列表、子任务区。继承字段有状态标记和“恢复继承”；改值/清空即成为独立字段。单击展开区默认只读，编辑进入详情，减少多处同时编辑。

输入停止 500ms 保存草稿，点保存才提交记录；保存成功清理该草稿。关闭有草稿时保留，下次打开提示恢复。草稿的 base_version 与服务器式“版本”一样只用于防止本地旧编辑覆盖新值；父任务继承变化也会使子任务版本增加。

搜索防抖 200ms，带递增查询序号，只采纳最后一次查询。取消数据库读取可能无法立即停止，但旧结果绝不能覆盖新结果。

### 10.3 管理窗口

月历、归档、回收站、设置共用一个管理窗口路由。设置包含默认附件目录、通知开关/提前量/静默时段、窗口模式与锁定、主题字号、快捷键、启动项、备份导入导出和诊断入口。

颜色用主题资源统一定义；正文 14–16 DIP，至少支持高对比、焦点可见和键盘 Tab/Enter/Esc。到期状态同时提供文字和辅助读取内容。V1 不使用持续动画、大面积背景模糊或网络字体。

### 10.4 默认视觉参数（Design Tokens）

对应 `Styles/Theme.axaml` 的极简瑞士风格默认参数（无需高保真原型即可直接落地实现）：

## 11. 备份、恢复、升级与卸载

### 11.1 两种备份

自动数据库备份：每日有变更后一次，保留 7 份，采用 SQLite 在线备份 API。不要运行中只复制 app.db，WAL 中可能有已提交数据。[Microsoft.Data.Sqlite BackupDatabase](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/backup)

完整备份：数据库快照、所选回收内容、所有受管理附件及目录结构、manifest.json。所有导入/迁移作业先到稳定点；暂停记录写入和附件变更直到快照/清单取得。外部编辑附件无法被数据库事务锁住，应对清单中的文件复制并校验变化，有变化重试或报告备份不完整，不能生成“成功”标记。

manifest 最少包含：`formatVersion=1`、`schemaVersion`、创建 UTC、设备 ID、根目录 ID 映射、每个附件相对路径/类型/大小/SHA-256、空目录清单、是否包含回收站、作业状态摘要。完成备份先写临时包，校验后原子改名。备份目录不能放在将被打包的附件目录树内部，避免自我递归。

### 11.2 恢复流程

1. 校验格式版本、文件清单、空间，拒绝绝对路径、`..`、链接和解压越界路径。
2. 让用户为根目录选择新位置，检测目标系统大小写及文件名冲突，生成不覆盖的名称映射。
3. 暂存解压、哈希核验、SQLite integrity_check/foreign_key_check；不直接覆盖当前库。
4. 备份当前数据，停调度器和数据库连接，持久化一份恢复操作日志。
5. 逐根发布已验证附件，原子切换本地数据库文件；不是多根目录跨盘原子事务，靠日志识别恢复阶段并重试。
6. 重建 storage_roots 映射与有效投影，旧设备 attachment_jobs 不允许执行源清理；通知去重保留，重新计算未来计划。
7. 重新打开并检查；失败按恢复日志回到旧库和旧映射，保留已发布新文件供后续处理，不自动删掉可能是唯一副本的数据。

### 11.3 升级和安装

MigrationRunner 在更新前做备份，然后逐个事务执行编号 SQL，记录 checksum（后续扩展 schema_migrations 时增加）。已执行的迁移文件不可原地修改；新版本添加迁移。恢复高于程序支持版本的库时拒绝打开并说明需要新版程序，不强行降级。

Windows 安装器采用用户级安装：配置应用位置、默认附件根目录、是否登录启动；把首次运行配置写到用户目录的独立文件，首次启动验证后导入 settings。启动开关读取系统真实状态，尊重用户在系统禁用启动项的选择。默认不要求管理员权限；数据库和附件不在安装目录。

发布命令在开发完成后使用：

```powershell
dotnet restore --locked-mode
dotnet test -c Release
dotnet publish src/DesktopNotes.Desktop -c Release -r win-x64 --self-contained true -p:PublishTrimmed=false -o artifacts/win-x64
```

自包含发布优先降低用户安装运行时的步骤，包体另测；不要在未验证反射、绑定和原生依赖前启用裁剪或 NativeAOT。安装器脚本建议放 `installer/windows/DesktopNotes.iss`，打包 `artifacts/win-x64` 的整个输出目录；不要只取 exe。

卸载默认保留应用数据与附件。用户明确选择清理时列出所有根目录与范围，仅清理本应用登记的 UUID 子目录，不能删除用户选择的整个附件根目录。

## 12. 验证矩阵与完成定义

| 类别 | 必测用例 | 通过条件 |
|---|---|---|
| 业务 | 空白、30字+emoji、四级排序、空 deadline、同值排序 | 与第4/5节一致，重启不变 |
| 搜索 | 合同/合 同/协议、大小写、百分号、单引号、正文尾部、空查询 | 字面语义正确，无 SQL 注入或错误通配 |
| 继承 | 父修改、独立空值、同值覆盖、恢复继承、日期冲突、完成快照 | 活动视图一致，历史字段不随父修改漂移 |
| 状态 | 完成/撤销、父子批量完成、删除批次、恢复父子 | 无孤立子任务、无静默批量完成 |
| 附件 | 同盘/跨盘、目录/空目录、重名、空间不足、占用、源变化 | 成功才清源；部分失败可恢复且可解释 |
| 崩溃 | planned/copying/verified/published/registered/cleaning 每阶段强退 | 重启对账不误删，重试不重复建附件 |
| 剪贴板 | copy/cut、未知标志、文本路径、拖入修饰键、导入期间复制新内容 | 符合约定，源与应用不重复清理 |
| 日期 | 日期型午夜、精确时间、时区改变、睡眠跨日、夏令时歧义 | 不误期，不重复轰炸通知 |
| 窗口 | Win+D、Explorer 重启、IME、外部文件拖入、125/150/200%缩放 | 真实桌面模式可见且可操作 |
| 恢复 | 多根附件、子任务标志、大小写冲突、路径穿越、不同机器 | 内容一致、不执行旧机器清源 |
| 性能 | 1万条记录、1000未完成、1GiB文件、1万小文件目录、8小时驻留 | UI可响应，指标有记录，无持续内存上涨 |

性能预算沿用计划书：冷启动≤2秒；列表交互 P95≤100ms；精准查询刷新 P95≤200ms（不含200ms输入防抖）；Windows 常驻 Private Bytes 目标≤150MB；空闲5分钟整机 CPU 平均<0.5%。预算未经应用实测，超标先定位，不修改数据集掩盖问题。

测试层级：Domain.Tests 纯规则，Integration.Tests 使用临时数据库和临时文件树，Desktop 手工/自动交互验收记录系统版本。验证文件操作不得使用用户真实资料；脚本递归删除前必须确认路径在测试临时目录内。测性能使用 Release、不连接调试器，保留测量脚本与原始数据。

Windows V1 完成需要：R01–R14 中属于 Windows 的必需项通过；故障恢复与备份演练通过；实际支持 Windows 构建列表明确；macOS/Linux 原型能力有报告；安装、升级和卸载验证；用户能找到数据与附件位置。Mac/Linux 正式发布各自单列完成状态。

## 13. 开发顺序与交付物

执行[逐步开发任务](superpowers/plans/2026-10-25-desktop-notes-v1.md)，每个任务完成后提交代码、测试与相关报告。依赖顺序：

```text
T01 工程与平台原型
  → T02 领域规则 → T03 SQLite与事务 → T04 子任务生命周期
  → T05 列表/详情/搜索 → T06 附件复制 → T07 移动/恢复/粘贴
  → T08 提醒/月历 → T09 窗口/设置/启动
  → T10 备份恢复 → T11 安装/性能验收 → T12 Mac/Linux发布
```

T01 只验证平台风险，T09 才完成正式系统集成。T06 的复制入口只是建立可测的传输基础，不能拿它替代 T07 的拖入移动。所有子任务和文件夹要求都在 Windows V1 内，不再推到“后续候选”。

最先交付的应是一份可运行原型及能力报告，而不是大量无平台验证的业务代码。每个模块按本指南数据和接口实现；需要变更契约时同步更新所有调用方、迁移、测试和 ADR。
